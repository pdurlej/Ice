# Fire 1.0.7 “Ignition”

Fire is a local, agent-first control plane for the space around your Mac's
menu bar. This is the recommended Fire 1.0 release.

## Highlights

- **Context Scenes** let Codex, Claude Code, or OpenCode propose menu bar
  behavior for the app, time, or battery context you are in. Fire shows the
  exact effect and installs it only after your approval.
- **Fireline** is a focused surface below the notch or menu bar. A scene can
  show one useful thing there, such as your local Codex or Claude quota, or a
  selected menu bar item.
- **Exact item selectors** distinguish multiple status items owned by the same
  app. Legacy bundle-only commands fail safely when they are ambiguous.
- **Fire CLI and agent skill** provide guided setup, diagnostics, and recovery
  without hand-editing JSON or configuration files.
- **Simpler Settings** organize setup, surfaces, contexts, agents, advanced
  controls, and the upstream Ice credit around real tasks.

## Fire 1.0.7 reliability

- Agent-facing XPC requests hand off their replies before starting async work.
  The listener remains available for the main-app relay, preventing Context
  Scene reads and consent-gated changes from deadlocking each other.
- Fresh CLI and agent sessions connect through the running Fire app rather
  than launching an isolated bundled XPC service. Reads, Context Scenes, and
  approved changes therefore meet in the same backend and consent relay.
- The Release server restores blocking semantics on each accepted local bridge
  socket before handing it to a worker, preventing a connect/read race from
  closing fresh CLI sessions with `EAGAIN`.
- Socket frames use explicit mutable buffers, and requests above a fixed 1 MiB
  bound are rejected.
- The local bridge transport mutually authenticates both executables using the
  kernel audit token, code validity, Developer ID team, exact executable path,
  and the current macOS user. Its socket is private to that user.
- Context Scene and write requests fail immediately with a clear setup message
  when Accessibility or Fire's menu-bar setup is not ready, instead of waiting
  for a relay timeout.
- XPC helpers use bounded Accessibility and request timeouts. A stopped helper
  cannot hang the agent bridge indefinitely, and failed connections are
  recreated on the next request.

## Compatibility

Fire keeps the existing `Ice.app` installation path and
`com.jordanbaird.Ice` bundle identity so current preferences, permissions,
Sparkle updates, saved layouts, and Keychain-backed approvals continue to work.
Because of that compatibility boundary, macOS System Settings may still list
Fire as **Ice** under Privacy & Security.
